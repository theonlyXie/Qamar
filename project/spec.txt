PART I
Product contract
One focused promise, one complete loop, and no false precision.
1. Product definition
1.1 One-sentence product
Product: Qamar is an Arabic-first, API-powered personal nutrition guide for Egyptian adults who repeatedly quit traditional diets. It understands Egyptian food, adapts the route after real life happens, and gives the user one useful next action without shame.
1.2 First user and job to be done
Dimension
Launch definition
Primary user
Egyptian adult, 18+, who has followed multiple diets briefly and stops after work, family meals, weekends, travel, stress, or one off-plan meal.
Functional job
Tell me what to eat, log what actually happened, and adapt the rest of my day.
Emotional job
Help me continue without treating a deviation as failure or forcing me to start again.
Social/cultural job
Understand Egyptian dishes, portions, routines, and conversational Arabic without making me translate my life.
Purchase reason
Always-available guidance and adaptation at a fraction of repeated human consultation cost.
1.3 Launch outcome
During the first session, an eligible user starts instantly under a private guest identity, understands the non-medical boundary, enters the minimum inputs needed for a nutrition estimate, receives a clear target and daily route, logs one real meal, confirms the estimate, and sees the day update. Qamar may offer a dismissible save prompt after target creation and repeats it after the first meal; only recovery, cross-device sync, export, or purchase requires linking. The interface ends with one next action—not a wall of charts.

2. Goals, non-goals, and success
2.1 Product goals
Reach first useful value in the first session and give an obvious reason to return tomorrow.
Make Egyptian meal capture faster than manual calorie reconstruction while keeping the estimate editable and honest.
Prove that route adjustment after deviations produces repeated use across at least three days.
Create a paid tier that expands usefulness without making the free core deceptive or unusable.
Build reusable Cipher Labs primitives without exposing future agents, AGI language, or Su publicly.
Keep variable AI cost, privacy, and safety controllable by design rather than founder heroics.

3.1 Definition of done for the public MVP
A new eligible user can install, start without a form, consent, complete onboarding, receive targets, log a meal, and then upgrade the same identity to a recoverable account without founder intervention.
Photo, voice, and text inputs all end in the same editable confirmation model; no estimate is recorded invisibly.
Today, Log, Plan, Progress, and You work through both standard navigation and the complete Qamar tree.
Tap, hold, and drag behavior of the movable Qamar orb works on both tested iOS and Android devices and remains accessible without gestures.
The free tier is genuinely useful; Qamar+ expands caps and depth; every offer clearly shows the current price, renewal price, billing period, and management path.
Quests, XP, levels, achievements, tree growth, recovery rewards, and Calm Mode work from a server-authoritative ledger without coins, broken streaks, leaderboards, body-outcome rewards, or pay-to-win multipliers.
Age, high-risk, privacy, export, account deletion, subscription restore, permission-denied, offline, API-error, and quota states have complete copy and behavior.
No API key or model credential is shipped in the app; all AI requests pass through the server gateway with schema validation and rate limits.
The release evaluation suite, store metadata, privacy policy, terms, account deletion, billing, and legal release gates pass before public distribution.

6.2 Daily logging and recovery journey
User opens Log from bottom navigation, tree, Today quick action, reminder deep link, or chat action.
User captures one meal by photo, voice, or text. The app shows processing progress and keeps the source recoverable during the request.
Qamar returns a structured draft with food items, portions, cooking method, calories/macros, source, and confidence.
The user edits uncertain items or answers at most one clarifying question, then confirms.
The meal is recorded and Today recalculates. Qamar shows one next decision and, if useful, offers to adjust the remaining plan.
If the target is exceeded, Qamar does not prescribe starvation, excessive exercise, or next-day compensation; it suggests a calm next meal or normal return tomorrow.
6.3 Subscription journey
No hard paywall appears before the user has a target and at least one meaningful result, except when the user intentionally opens Qamar+.
If the user is still a guest, the purchase CTA opens a one-tap Save progress sheet. Successful linking returns directly to the selected product without losing the paywall or offer.
A quota or premium action opens a contextual explanation, then the full paywall with Free versus Qamar+ comparison.
Quarterly 750 EGP is the recommended hero package; monthly 349 EGP and annual 2,400 EGP remain visible and selectable.
Eligible new accounts may receive a store-managed 14-day Qamar+ introductory trial. Promotional eligibility may change the first-period price. The screen must disclose trial end, billing period, renewal price/date, and cancellation/management path before purchase.
Receipt verification updates the server entitlement; success returns the user to the exact blocked action. Failure preserves context and offers retry/restore.
6.4 Return-after-absence journey
Recovery rule: Never show a broken-streak failure screen. The returning user sees a short welcome, the current route, and one action that can be completed now.

7. Accessibility and Arabic RTL requirements
Area
MVP requirement
RTL
All primary layouts, navigation order, alignment, drawers, chips, and progression copy use Arabic right-to-left direction.

Mirror directional navigation icons and progress chevrons; do not mirror media controls, camera orientation, brand mark, or universally directional symbols.
Numbers
Store numeric values independent of presentation; respect locale where practical; keep number-unit clusters readable (for example 120 جم).
Charts
Chronological plots remain left-to-right for conventional reading; Arabic titles, legends, and annotations remain RTL.
Contrast
Normal text >= 4.5:1; large text and essential icons >= 3:1; focus indicator is visible on every interactive element.
Targets

Dynamic text

Voice/photo

9.2 Target calculation product rules
Use a deterministic target service; the language model may explain a result but never calculates or invents final calorie/macro values.
Record formula version, input values, activity factor, goal adjustment, safety clamps, and timestamp so the target is auditable and recalculable.
Macro allocation is configurable and expressed in grams; hard preference/allergy rules affect food selection, not unreviewed medical prescriptions.
The target screen says the values are estimates for general wellness, identifies the assumptions, and offers edit/recalculate—not medical certainty.
Any exact lower/upper energy floor, pace boundary, or clinical exclusion must live in a versioned Nutrition Policy Table and pass the release safety/legal gate; it is not embedded in prompts.
A meaningful change to age band, weight, goal, activity, or safety input invalidates the current target and plan until the user confirms recalculation.

25.2 Structured response requirements
Every tool-capable workflow uses a versioned schema. Reject or repair invalid outputs server-side; never pass raw malformed content to the app.

29.3 API conventions and reliability
Concern
Contract
Specification
OpenAPI 3.1 is canonical. Generate typed Dart models/clients and server validators from versioned schemas; contract tests run in CI.
Envelope/errors
JSON success payload + request_id; typed error {code, message_key, retryable, field_errors}; never send raw provider errors to app.
Authentication
Short-lived bearer access token. Server derives user from token; never accepts user_id ownership from request body.
Idempotency
Required on confirmation, plan changes, game-triggering writes, purchases/sync, exports and deletion. Same key/body returns same result.
Concurrency
ETag/version or expected_version on mutable records; 409 conflict returns latest canonical record and recovery instruction.
Pagination/time
Cursor pagination; ISO-8601 UTC timestamps; user locale/time zone only at presentation and scheduling boundaries.
Streaming
SSE for chat with named progress/tool states, terminal completion/error, cancellation and resumable conversation ID.
Retry
Exponential backoff + jitter only for retryable idempotent calls; honor Retry-After; circuit-break providers; preserve user input.
Rate/cost
Per user/device/IP/workflow quotas; entitlement-aware budgets; daily provider spend alerts and kill switches preserving manual core.
Logging
request_id, route, status, latency, versions and cost band only; redact tokens, bodies, media URLs, contact/body/nutrition/chat data.
Webhooks
Verify signature/auth before parsing, persist provider event ID once, return quickly, process async, retry safely, dead-letter failures.
Secrets
Server secret manager/env only; separate dev/staging/prod keys; rotation runbook; mobile contains only publishable configuration.
